## 1. 「状態リセット」アクションのスコープ（world-creation.md 9.8 / 14.5）

**背景**: ResetState はステート（ワールド / プレイヤー）のみリセットする実装。
しかし 14.5 は「BGM オーバーライドは状態リセットまで維持」と定義しており、
どの ResetTarget が BGM を戻すのか不明。タイマー・インベントリ・オブジェクト表示状態を
含むかも未定義。9.10 のループ検知時「ルームを初期状態にリセット」のスコープも同様。

**決めること**:
- ResetTarget = World / All のとき: タイマー・BGM オーバーライド・オブジェクト表示 /
  種類切り替え状態・インベントリ・進行中の移動を初期状態に戻すか
- ResetTarget = InputPlayer / OpponentPlayer / AllPlayers のとき: 対象プレイヤーの
  インベントリを返却するか（現実装はステートのみ）
- 移動速度（100% 復帰）・頭上マーカー（消去）はどの ResetTarget に含まれるか
  （9.8 の仕様文は「状態リセットで戻る」とのみ記載）
- 9.10 ループ検知時のリセットは ResetTarget.All と同一処理でよいか

**推奨**: All = 全要素（タイマー / BGM / オブジェクト状態 / インベントリ / 移動 / 速度 / マーカー）を初期化。
World = ワールドステート + BGM + オブジェクト状態。
プレイヤー系 = ステート + インベントリ返却 + 速度 100% + マーカー消去。
ループ検知時 = All と同一。

## 2. 数字オブジェクトの細部仕様（world-creation.md 3.9）

**決めること**:
- **「ルーム参加 X 番目」の繰り上がり**: プレイヤー退室時に参加順番号が詰まる
  （現実装: 現在の在室者リスト順 = 詰まる）か、セッション中固定かつ欠番ありか
- **固定値の範囲と表示桁数**: ステート参照は 0〜255（3 桁）だが固定値の範囲が未定義。
  負数・桁数上限（描画メッシュ・テクスチャ設計に直結）
- **参照先プレイヤー不在時の表示**: 現実装は 0 を返す。「0 表示」か「非表示 / ハイフン」か
- **描画方式**: 桁ごとのメッシュ切り替えか、数字テクスチャアトラスの UV 切り替えか
  （Unlit 1 ドローコール制約との整合）

**推奨**: 参加順は「在室者の参加順で詰める」（現実装どおり）。固定値 0〜999（3 桁・負数なし）。
不在時は 0 表示。

## 3. テクスチャコスト判定の正確な定義（world-creation.md 4.3）

**決めること**:
- **「ギミックで非表示」の判定方法**: コスト対象外となる「非表示のオブジェクト種別」を
  エディタがどう判定するか。案: 「初期状態が非表示で、かつ表示に切り替えるアクションが
  ルール中に存在しない種別」のみ対象外（実行時に表示され得るものはコスト対象）
- **種類切り替え先に保存バリアントを指定できるか**: 現実装（`TextureCostCalculator` の
  `switchTargetTypeIds`）は ID を不透明に扱うためどちらでも動くが、UI とコスト計算で確定が必要
- **オブジェクトの初期表示状態**: 配置オブジェクトに「初期非表示」フラグを持たせるか
  （ワールド定義 JSON のフィールド追加）

**推奨**: 初期非表示フラグを JSON に追加し、「初期非表示 かつ 表示アクションなし」をコスト対象外とする。

## 4. ネットワーク権威モデルの明文化（world-creation.md 9.1 / 9.4）

**背景**: 9.4 は「ルール評価はルームオーナーが行い、結果を全クライアントに送信」とあるが、
9.2 のタイマーイベントは「各クライアントがローカル監視して発火 → オーナーが権威的に確認」とあり、
クライアント側でもエンジンを動かすのか曖昧。

**決めること**:
- エンジン実行はオーナーのみか（非オーナーは `GimmickEffect` リストの適用のみ行うか）
- タイマーイベントの検知責務: オーナーのみの監視で十分か（9.2 の記述の整理）
- 範囲乱数の共有方法: オーナー評価 + エフェクト送信モデルなら、エフェクトに解決済みの値
  （例: `WorldStateChangedEffect.NewValue`）が入るため追加の乱数同期は不要 — これを明文化するか
- エフェクト送信の形式（Netcode for GameObjects の RPC / NetworkVariable のどちらで運ぶか）

**推奨**: オーナーのみ評価・エフェクト適用方式（現エンジン設計と一致）。乱数の個別同期は不要と明記。
